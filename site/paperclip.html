Paperclip Integration

Running an autonomous AI agency with SCRUM MCP.

How SCRUM MCP's inbox injector turned 7 idle AI agents into a functioning digital agency completing 12 issues per cycle instead of zero.

The Story

SCRUM MCP was built to coordinate multi-agent AI development — intent declarations, file claims, evidence receipts, compliance checks. It worked well for software engineering tasks where Claude Code agents needed to collaborate without conflicts.

But the real test came when we adopted Paperclip to run Morpheos — an autonomous digital agency with 7 AI agents managing 4 web properties simultaneously.

The Problem

Heartbeats Without Work

Paperclip's heartbeat system wakes agents every 10 minutes. The agents are routed through an LLM gateway (OpenClaw) as chat messages — they lack direct tool access. They cannot call REST APIs, cannot checkout issues, cannot update task status.

Every 10 minutes, each agent
Agent wakes up via heartbeat
Agent has no context about assigned issues
Agent has no API access to query Paperclip
Agent responds: "I'm alive. Standing by for instructions."

Output: 2.8KB / 15 seconds
Issues completed: 0
Actual work done: None

The result: every heartbeat completed in 5-30 seconds with 2.8KB of output. Agents were just pinging "I'm alive" without doing any work. Zero issue completions per cycle. Zero progress.

The Solution

Inbox Pre-Processor

SCRUM MCP's inbox injector bridges the gap. Instead of agents calling APIs (which they cannot do), the APIs come to them.

1
Pre-fetch
Query Paperclip DB for each agent's assigned issues (todo, in_progress, blocked)
2
Materialize
Inject the issue queue directly into the agent's heartbeat prompt
3
Instruct
Include role-specific work priorities and the quality gate protocol
4
Refresh
Run every 9 minutes via systemd timer, keeping context fresh
Architecture

The Data Flow

The inbox injector sits between Paperclip's database and the agent heartbeat system, materializing each agent's work queue into their prompt context.

System Architecture
Paperclip DB (issues, agents, goals)
    |
    | (every 9 min)
    v
SCRUM Inbox Injector (inject-inbox.py)
    |
    | (updates adapter_config.payloadTemplate)
    v
Agent Heartbeat Prompt
    |
    | (includes: role + inbox + protocol + quality rules)
    v
LLM Gateway (OpenClaw -> Gemini/DeepSeek/etc.)
    |
    v
Agent Response (analysis, decisions, status updates)
    |
    | (parsed back into Paperclip)
    v
Issue Status Changes (todo -> in_progress -> in_review -> done)
Quality Gate

No Agent Marks Their Own Work Done

The quality gate ensures every piece of work gets independently verified before it can be marked complete. No self-grading allowed.

Agent completes work
Sets issue status to in_review
Socrates receives ALL in_review items
Quality auditor's inbox is automatically populated with every item awaiting review
Pass: done with audit report
Socrates fetches URLs, verifies content exists, checks deliverables, and approves
Fail: returned to todo with failure report
Detailed failure report sent back to the originating agent for rework

Setup Guide

Getting Started

Prerequisites

  • Paperclip v0.3+ with agents configured
  • Python 3.10+ on the Paperclip host
  • Access to Paperclip's PostgreSQL database

Installation

Install the inbox injector
# Copy the inbox injector to your Paperclip installation
cp scripts/inject-inbox.py /path/to/paperclip/scripts/

# Create systemd timer (runs every 9 minutes)
# See dashboard/paperclip-inbox-inject.service and .timer
sudo systemctl enable --now paperclip-inbox-inject.timer

Agent Prompt Templates

Each agent needs a role-specific prompt template set in adapter_config.promptTemplate. The inbox injector automatically appends the issue queue to each agent's template on every cycle.

Example: Quality Auditor (Socrates)
# Example prompt template
template = """You are Socrates, Quality Auditor.
YOUR PRIMARY JOB: Audit ALL in_review items.
Fetch URLs, verify content, check deliverables.
Pass -> done with report. Fail -> todo with failure report."""
